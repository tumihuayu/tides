# 页面结构重梳理与 UI 改版 — 需求分诊报告

日期：2026-09-04
分诊人：测试PM agent
需求：重新梳理页面关系为「登录界面 → 新手教程 / 首页 → 个人界面」4 界面结构并查漏补缺；UI 色调与背景参考《锚点降临》改版。

## 1. 现状页面结构摘要

客户端为单页多 screen 结构，`AppState.screen: 'lobby' | 'game' | 'tutorial' | 'entry'`（client/src/ui.ts:18），由 main.ts `render()` 按 `accountStatus` + `screen` 分支渲染：

| 目标界面 | 现状对应 | 现状说明 |
|---|---|---|
| 登录界面 | `entry`（entry.ts） | 已有。含「进入新手教程 / 登录 / 注册」三按钮，文案「欢迎登船」。仅首次访问（无 `tides_entry_seen` 且无 session）时展示（main.ts:15） |
| 新手教程 | tutorial.ts | 已有。3 页图文（PAGES，tutorial.ts:15-19），纯客户端 |
| 首页 | `lobby`（lobby.ts） | 已有。含创建房间、房间码加入、在线房间列表（含刷新）、登出按钮、新手教学/我的战绩/排行榜入口、昵称输入、服务器地址调试行 |
| 个人界面 | **不存在** | 仅有大厅弹层「我的战绩」（panel='stats'）与「排行榜」（panel='leaderboard'），ui.ts:14 的 `LobbyPanel` 只有 `none/stats/leaderboard` |
| 游戏对局 | `game` | 与本需求无关，保持 |

### 登录/注册现状（已完整）
- 登录/注册模态框 `openAccountModal(mode)`（main.ts:164），支持登录↔注册切换、确认密码、完整前端校验（账号名 3-64 仅 `[A-Za-z0-9_-]`、密码 8-256、两次一致，main.ts:210-234）。
- 服务端错误码已齐全并在前端映射为中文提示（main.ts:589-599）。
- 会话持久化：localStorage `tides_account_session` + `session` 消息恢复，30 天有效期；断线有顶部横幅 + 重连钩子（main.ts:644-652）。

## 2. 差距分析（目标 vs 现状）

| # | 差距 | 现状证据 | 建议 |
|---|---|---|---|
| G1 | 教程完成后**不会返回登录界面** | 游客完成教程后停在「注册账号并进入大厅」页（tutorial.ts:55-68）；从入口点教程则直接进入游客教程流（main.ts:65-71） | 教程「完成」后返回登录界面（entry），注册引导可保留为完成页上的可选按钮 |
| G2 | 登出后**不会返回登录界面** | `logged_out` 后 screen 停在 lobby，未认证分支渲染游客教程介绍页（main.ts:441-449 + 77-90） | 登出成功 → `screen='entry'`，回到登录界面 |
| G3 | 登录界面**只在首次访问出现**，老用户/登出用户看不到 | main.ts:15 首屏判定依赖 `tides_entry_seen` | 调整为：未认证一律先落登录界面（教程完成/登出/会话失效均回到 entry） |
| G4 | 登出按钮不在右上角 | 登出在 lobby 账号面板内（lobby.ts:183-188） | 首页右上角固定登出按钮；保留账号状态标识 |
| G5 | **个人界面整体缺失** | 无 profile screen；ui.ts:14 panel 类型不含 profile | 新增个人界面：① 个人信息展示（账号名/战绩摘要，可复用 `get_my_stats`）② 密码修改 ③ 游戏说明；需返回首页入口 |
| G6 | **游戏说明与新手教程关系未定义** | 大厅已有「查看规则 / 重玩教学」按钮（lobby.ts:255-256）打开同一份 3 页教程 | 需策划明确：游戏说明=静态规则文本（可复用教程 3 页文案），教程=首次引导流；避免两处内容重复维护 |
| G7 | 登录界面不展示登录/注册失败原因 | 失败后仅 toast + `accountNotice`，而 accountNotice 只渲染在 lobby 账号面板（lobby.ts:222），entry 屏看不到 | 登录/注册失败提示需落在模态框内或 entry 屏可见位置 |
| G8 | 首页遗留调试元素 | 服务器地址输入行（lobby.ts:232-249） | 建议收入个人界面「设置」或隐藏到调试参数后，正式首页不出现 |
| G9 | 首页「我的战绩/排行榜」入口与新结构的关系 | lobby.ts:253-264 | 建议战绩并入个人界面，排行榜保留首页；需产品确认 |

## 3. 服务端协议确认结果（关键结论）

| 需求功能 | 协议现状 | 结论 |
|---|---|---|
| 登录/注册/登出/会话恢复 | `register`/`login`/`logout`/`session`（shared/protocol.md:26-29） | ✅ 已支持，无需改 |
| **修改密码** | **不存在**。`tides_account.erl` 仅导出 `register/login/logout/session/role`（tides_account.erl:5）；`tides_ws_conn.erl:376-434` 消息分发无此类 type；protocol.md 无相关消息 | ❌ **需后端新增**：建议 `change_password {old_password, new_password}`，复用现有密码校验规则与错误码，新增 `wrong_old_password`；需决策改密后旧 session 是否全部失效（安全建议：是） |
| **个人信息查询** | 无独立账号信息协议。`logged_in` 返回 `account_name/role_id`；战绩可查 `get_my_stats`（protocol.md:38） | ⚠️ 部分覆盖：若个人信息=账号名+战绩摘要则零协议改动；若需注册时间等账号字段，需新增 `get_account_info` |

**这意味着本次需求需要后端 agent 配合**（至少 change_password），协议与数值变更须由主协调同步 shared/protocol.md。

## 4. 查漏补缺建议（用户方案遗漏点）

1. **游客身份去留**：现有游客流程（enterGuest，main.ts:277-285）在新 4 界面结构中无位置。建议：登录界面保留弱化的「游客试玩」或彻底移除，需产品确认。
2. **表单校验**：已有（G 项见上），但修改密码表单需新增校验：新密码 8-256、两次一致、新旧密码不能相同。
3. **登录态持久化/断线**：已有 session 30 天 + 断线横幅 + 房间重连，无需新需求；但**会话失效**（`session` authenticated=false）后应回登录界面（main.ts:451-465 当前停在未认证游客流）。
4. **返回路径完整性**：个人界面需「返回首页」；游戏说明需「返回个人界面」；教程每页已有「返回/关闭」，完成页需「返回登录」。
5. **UI 改版资源清单**（当前无任何图片资源，纯 CSS 渐变，styles.css 采用 navy/tide/gold 配色变量）：
   - 各屏背景图（登录/首页/个人/教程，含 2x 分辨率与宽屏适配策略）
   - Logo/标题字、按钮质感稿、图标（登出、个人、返回等）
   - 配色 token 表（替换 :root 变量组）与字体授权确认
   - 《锚点降临》为科幻二次元美术风格，**注意仅参考色调与构图，素材必须原创或获授权，避免版权风险**
   - 需策划 agent 先出 UI 风格稿/资源规格，前端再实施
6. **首访标记语义变化**：`tides_entry_seen` 若按 G3 调整将失去意义，建议移除或改为控制教程自动播放。
7. **冒烟脚本影响**：tests/robot.mjs 走协议层不受影响；UI 类静态验收文档（entry_screen_acceptance.md 等）需在改版后同步更新。

## 5. 验收标准清单

### A. 登录界面（entry）
- [ ] 未认证用户打开站点、登出后、会话失效后，均落在登录界面
- [ ] 登录界面含且仅含主功能：登录、注册、新手教程
- [ ] 登录失败（错误密码/格式错误/断线）在登录界面可见中文提示，不跳屏
- [ ] 注册失败（账号已存在/校验不通过）提示可见；注册成功自动登录进首页
- [ ] 持有效 session 打开站点直接进首页（不强制看登录界面），不回归

### B. 新手教程
- [ ] 从登录界面进入教程，仍为 3 页，可翻页/返回
- [ ] 第 3 页点「完成」后返回登录界面
- [ ] 教程全程不发送业务协议（仅连接/ping）

### C. 首页
- [ ] 含创建房间、进入房间（房间码）、查看在线房间（列表+刷新）
- [ ] 右上角有登出按钮，点击后回到登录界面
- [ ] 有进入个人界面的入口
- [ ] 房间内时不允许登出（现有保护不回归）
- [ ] 登录态下刷新页面仍在首页且房间列表自动刷新

### D. 个人界面
- [ ] 展示个人信息（至少账号名；战绩摘要可复用 get_my_stats）
- [ ] 密码修改：旧密码错误提示 `wrong_old_password`；新密码校验（8-256/两次一致/不同于旧密码）；成功提示并按约定处理旧 session
- [ ] 游戏说明可打开查看，可返回个人界面
- [ ] 个人界面可返回首页
- [ ] 未认证状态无法通过任何路径进入个人界面

### E. 服务端协议（如实施 change_password）
- [ ] eunit 通过；新增改密用例：成功、旧密码错误、格式错误、未认证
- [ ] 20 局自玩模拟通过（AGENTS.md 常用命令）
- [ ] `node tests\robot.mjs` 4 人整局冒烟通过

### F. UI 改版冒烟验证点
- [ ] `cd client && npm run build` 通过（无 TS 错误）
- [ ] 四个界面背景图/配色按策划稿落地，1366×768 与 1920×1080 下无破版、文字对比度可读
- [ ] 图片资源体积合理（建议单图 ≤500KB 或懒加载），首屏加载无明显白屏
- [ ] 断线横幅、toast、模态框在新配色下可读
- [ ] 所有按钮 hover/disabled 态可见区分
- [ ] 无图片资源 404（浏览器 network 面板检查）

## 6. 建议执行顺序

1. 策划 agent：确认查漏补缺决策点（游客去留、游戏说明与教程关系、排行榜/战绩入口归属）+ 出 UI 风格稿与资源规格。
2. 主协调：同步 shared/protocol.md（change_password、视情况 get_account_info、新错误码、改密后 session 策略）。

4. 前端 agent：页面结构改造（个人界面、返回路径、登出位置、登录失败提示落点）+ UI 改版。
5. 测试PM：按第 5 节验收，更新既有 UI 静态验收文档，出验收报告。
