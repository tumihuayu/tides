# 《潮汐商会》M0 新玩家流程测试与验收基线

状态：基线文档，待 M0 实现后执行  
版本：M0  
依据：`tests/test_plan.md`、`tests/acceptance_checklist.md`，以及本轮已确认的产品决策。  
适用环境：客户端正式构建、服务端正式规则版本、可清理的测试账号/浏览器存储。  

本文只定义测试和验收基线，不定义实现方案，也不要求在本轮新增自动化代码。所有实际执行结果须记录版本、日期、环境、测试身份和证据链接。

## 1. 已确认决策

M0 新玩家引导由以下三段组成，顺序和可达性均属于验收范围：

1. 静态说明：解释基础目标、回合/行动、资源和结算的最小规则。
2. 固定任务教程：独立于普通房间，使用固定资源和预设任务，真实行动由服务端权威处理。
3. Easy bot 陪练：默认 `1 名真人 + 1 名 easy bot`，使用正式规则完成可结束的对局。

身份口径（覆盖旧 player_token 统计假设）：

- 游客无 `role_id`/`PlayerProcess`，只能进行纯客户端教程；游客不产生任何统计。
- 账号教程状态以账号会话/账号 ID 为归属；旧 `player_token` 仅用于 LEGACY 兼容检查，不得绑定账号、role 或教程完成事实。
- 测试身份由 `robot.mjs --player-token=`、`TEST_PLAYER_TOKENS` 或隔离账号 fixture 注入；服务端返回的房间 token 不是账号身份。

其他决策：

- 固定任务教程不是普通房间，不能被普通房间玩家加入、观战或干扰。
- 教学局不计正式战绩、胜场、排行榜，也不产生任何奖励。
- 教程支持跳过、退出、重玩；跳过和退出不会伪造“已完成”。
- 登录账号在服务端保存教程完成状态；游客仅在本地保存。
- 游客完成状态不自动迁移到登录账号，登录后须按账号状态重新判断；教程结束只能注册或退出。
- 基础教程使用固定资源；陪练使用正式规则，而不是教程脚本规则。
- 首版不验收奖励系统和复杂埋点；不得因缺少奖励/埋点阻塞 M0。

### 2.2 明确不在 M0 验收范围

- 奖励、道具、成就、任务奖励发放。
- 复杂埋点、漏斗分析、行为上报完整性和数据看板。
- hard bot 或其他 bot 难度平衡；仅验证 easy bot。
- 教程资源编辑器、动态任务配置和多套教程内容。
- 教学内容的多语言验收，除非当前构建已宣称支持该语言。
- 普通房间规则重做；正式规则回归仍按 `test_plan.md` 的 RC/RJ/DC/SC 用例执行。

## 3. 状态模型与边界

### 3.1 教程状态

测试中使用以下业务状态名称描述预期，不规定协议字段名：

| 状态 | 含义 | 允许操作 | 完成标记 |
|---|---|---|---|
| `not_started` | 身份没有完成记录 | 开始、跳过、离开 | 否 |
| `in_progress` | 当前存在未完成的教程会话 | 继续、退出、重玩（按产品入口） | 否 |
| `completed` | 已成功完成固定任务教程 | 查看结果、重玩、进入陪练 | 是 |
| `skipped` | 用户主动跳过说明或教程 | 进入后续引导、稍后重试 | 否，除非产品明确把“跳过整段”定义为完成；本基线按否验收 |
| `exited` | 用户中途退出教程 | 重新开始/继续（按最终交互） | 否 |

若实现不暴露上述状态名，须能用界面表现和持久化结果等价证明状态转换。

### 3.2 身份与存储矩阵

| 身份 | 完成教程后的保存位置 | 换设备/重启后 | 登录另一个账号 | 登录已有账号 |
|---|---|---|---|---|
| 登录账号 A | 账号服务端 | 仍为完成 | A 的状态不影响 B | 显示 A 的服务端状态 |
| 游客 G | 当前设备本地 | 同浏览器/本地存储仍在 | 不适用 | 不迁移 G 状态；按账号自身状态判断 |
| 清除游客本地数据 | 无记录 | 回到未完成 | 登录账号不受影响 | 按账号服务端状态判断 |

### 3.3 必测边界

- 首次进入、只读浏览、快速连续点击、刷新和浏览器前进/后退。
- 教程开始前、任务进行中、完成判定前、结果页和陪练进行中退出。
- 教程完成后再次进入：重玩不覆盖完成状态，不重复产生正式数据。
- 登录前完成游客教程，再登录新账号：账号不能被自动标记完成。
- 登录账号在设备 A 完成后，在设备 B 或清空本地存储重新登录：仍显示完成。
- 账号服务不可用/超时、游客本地存储不可写、存储数据损坏或版本未知。
- 教程固定资源与任务被客户端篡改、伪造完成消息、越权提交他人行动。
- easy bot 未及时行动、真人断线重连、真人主动退出；不得导致房间或正式统计异常。
- 教学局与普通房同时进行；教学玩家不得出现在普通房 `list_rooms`、在线玩家或正式对局成员中。
- 最小可用陪练人数为 1 真人 + 1 easy bot；不得因等待第二名真人而无法开始。

## 4. 测试分组与用例

### NP-A 入口与三段式流程

| 编号 | 前置/步骤 | 预期 |
|---|---|---|
| NP-A01 | 清理新身份，首次进入游戏 | 展示静态说明入口，明确后续固定任务教程和 easy bot 陪练；无完成状态误判 |
| NP-A02 | 完成静态说明 | 可进入固定任务教程；顺序无跳段、无死循环 |
| NP-A03 | 完成固定任务教程 | 可进入默认陪练；陪练配置为 1 真人 + 1 easy bot |
| NP-A04 | 在任一段刷新/重新打开 | 回到可解释的稳定入口；不重复扣资源、不产生孤儿房间、不丢失已确认状态 |
| NP-A05 | 已完成教程身份再次进入 | 明确显示已完成；仍可选择重玩和陪练，不强制重复新手流程 |
| NP-A06 | 旧客户端/无新手状态数据登录 | 按未完成处理；不得因缺字段崩溃或误标完成 |

### NP-B 静态说明

| 编号 | 前置/步骤 | 预期 |
|---|---|---|
| NP-B01 | 逐页阅读说明 | 覆盖目标、回合流程、六类行动、资源/货物、潮汐和终局结算的最小可行动信息 |
| NP-B02 | 桌面端和窄屏移动端打开 | 文字、按钮、滚动区域不截断、不遮挡；可完成下一步/返回 |
| NP-B03 | 说明页点击开始/跳过/返回 | 只改变引导导航，不创建房间、不写正式战绩 |
| NP-B04 | 2 名无桌游经验受试者阅读后首次行动 | 在不依赖测试人员补充规则的情况下，均能在 10 分钟内完成首次合法行动；记录耗时和误操作 |

### NP-C 固定任务教程与服务端权威

| 编号 | 前置/步骤 | 预期 |
|---|---|---|
| NP-C01 | 从入口开始固定任务教程 | 进入专用教学会话；有明确教程标识，不能以普通房间形式出现在房间列表 |
| NP-C02 | 记录初始资源、手牌、港口、任务 | 每次新开/重玩得到同一套固定资源和任务，结果可与基线快照对比 |
| NP-C03 | 按提示提交合法真实行动 | 行动经服务端校验并结算；客户端展示的状态与服务端快照一致 |
| NP-C04 | 发送缺少/伪造 `action_id`、非法 card、越权目标或不满足资源条件的行动 | 服务端拒绝；状态、任务进度和完成标记不被非法请求推进 |
| NP-C05 | 修改客户端显示资源/任务或重放完成请求 | 服务端仍以权威状态判断；不能伪造教程完成 |
| NP-C06 | 按任务要求完成教程 | 收到/展示明确完成结果；完成只在任务真实满足后发生，不以打开页面或点击按钮替代 |
| NP-C07 | 教程中观察其他连接/普通玩家 | 不泄漏教学会话内部状态，不允许外部玩家操作或改变教学局 |
| NP-C08 | 同一身份并发打开两个教程会话 | 按产品策略拒绝、复用或关闭旧会话，但不能双重结算、状态回退或留下孤儿会话 |

### NP-D 教学局隔离与正式数据

| 编号 | 前置/步骤 | 预期 |
|---|---|---|
| NP-D01 | 教程进行中调用/观察 `list_rooms` | 教学会话不作为普通可加入房间列出 |
| NP-D02 | 教程进行中创建/加入普通房间 | 两种会话的玩家身份、连接、状态和消息互不串扰；按产品限制给出明确提示 |
| NP-D03 | 教学完成后查询个人战绩、胜场、排行榜 | `games`、`wins`、`ladder`、排行榜排名和正式 `recent` 不因教程变化 |
| NP-D04 | 教程退出/完成后检查服务器房间与进程 | 会话按规则结束并释放；无普通房间残留玩家、定时器、行动或统计写入 |
| NP-D05 | 教程局触发终局/重复请求终局 | 仅产生教学完成结果，不产生正式 `game_over` 计分记录；重复请求幂等 |
| NP-D06 | 教程与正式房同时完整运行 | 正式房仍可正常推进和结算；教学消息不进入正式房 `state_sync/action_log` |

### NP-E 跳过、退出与重玩

| 编号 | 前置/步骤 | 预期 |
|---|---|---|
| NP-E01 | 静态说明点击跳过 | 进入约定的下一段；不写教程完成状态，除非仅标记该段已跳过 |
| NP-E02 | 教程开始前退出 | 返回安全入口；不创建可见普通房、不写完成、不写正式战绩 |
| NP-E03 | 教程进行中退出并确认 | 会话结束；状态为未完成/已退出，重新进入可从约定位置开始，资源重新为固定基线 |
| NP-E04 | 教程进行中取消退出 | 保持当前状态和任务进度，不重复提交当前行动 |
| NP-E05 | 完成教程后选择重玩 | 新教程仍使用固定资源/任务；重玩过程真实可操作，完成状态保持为已完成 |
| NP-E06 | 连续完成、退出、重玩多次 | 无重复正式统计、无重复奖励（M0 无奖励）、无状态回退、无服务端崩溃或会话泄漏 |
| NP-E07 | 陪练中主动退出 | 退出提示清晰；房间和 bot 正常收束，不计正式战绩；可再次开始陪练 |

### NP-F 登录账号与游客状态

| 编号 | 前置/步骤 | 预期 |
|---|---|---|
| NP-F01 | 登录账号 A 完成教程，退出并重新登录 A | 完成状态保留；清空浏览器本地存储后重新登录仍为已完成 |
| NP-F02 | 账号 A 在设备/浏览器 1 完成，设备/浏览器 2 登录 A | 服务端状态一致，显示已完成；不要求依赖设备 1 的本地数据 |
| NP-F03 | 游客 G 完成教程，刷新/重启同一浏览器 | 本地完成状态保留；服务端账号战绩无变化 |
| NP-F04 | 游客 G 完成后登录从未完成的账号 B | 不自动迁移 G 的完成状态；B 按自身状态显示未完成 |
| NP-F05 | 游客 G 完成后登录已完成的账号 A | 显示 A 的账号状态；不得把 G 的状态写入 A 或改变 A 的完成时间/版本信息 |
| NP-F06 | 账号 A 未完成，游客完成后退出账号再登录 A | A 仍未完成；游客本地状态和 A 的服务端状态相互隔离 |
| NP-F07 | 账号状态请求失败/超时 | 有可理解的错误或重试提示；不得把失败误判为已完成，也不得覆盖已有完成状态 |
| NP-F08 | 游客本地存储被清除/损坏/禁用 | 回退到未完成或明确降级提示；应用不崩溃，登录账号状态不受影响 |

### NP-G Easy bot 陪练

| 编号 | 前置/步骤 | 预期 |
|---|---|---|
| NP-G01 | 新玩家选择陪练 | 默认自动创建 1 真人 + 1 easy bot，不要求等待第二名真人；bot 标识和难度可识别 |
| NP-G02 | 陪练中逐回合提交合法行动 | 使用正式规则、正式资源和正式结算；不是固定教程脚本，状态与正式 2 人局规则一致 |
| NP-G03 | 观察 bot 回合 | easy bot 在约定时限内提交合法行动；无持续 `action_rejected`、不依赖 45s 超时兜底、对局可推进至终局 |
| NP-G04 | 真人提交非法行动/篡改目标 | 服务端拒绝且不破坏 bot 调度、回合和真人状态 |
| NP-G05 | 真人断线后在宽限期内重连 | 恢复本人私有状态；bot 不重复提交，回合不双结算 |
| NP-G06 | 真人主动退出或断线超出既有托管规则 | 会话按正式房间既有回收/托管规则收束，不阻塞、不计正式战绩 |
| NP-G07 | 陪练终局后查询正式数据 | 不增加 games/wins/ladder，不进入排行榜；正式规则结算只用于陪练过程展示 |
| NP-G08 | 重玩陪练至少 3 次 | 每局均能正常开始和结束；无跨局状态、bot 身份、定时器或统计残留 |
| NP-G09 | 陪练期间打开普通房/教程入口 | 导航行为明确；不同会话不互相发送行动或覆盖进度 |

## 5. 执行分组与优先级

### P0 阻塞验收

必须执行并全部通过：NP-A01~A03、NP-B01~B03、NP-C01~C06、NP-D01~D06、NP-E01~E07、NP-F01~F08、NP-G01~G04、G07~G08。  
P0 覆盖 39 条本基线用例。任何服务端崩溃、教学越权、正式数据污染、身份状态错误、无法完成三段流程，均为阻塞问题。

### P1 上线前回归

NP-A04~A06、NP-B04、NP-C07~C08、NP-G05~G06、G09，以及现有 `test_plan.md` 的正式规则、非法行动、断线重连、隐藏信息和人机回归。P1 可有经批准的低风险体验缺陷，但不得影响 P0 结果。

### 测试分层

1. 静态检查：说明内容、入口文案、教程资源快照、难度和房间类型标记。
2. 客户端手工/浏览器：导航、响应式布局、退出确认、登录/游客显示和错误提示。
3. 协议/服务端：真实行动校验、固定资源、教程隔离、幂等、身份持久化和统计排除。
4. 联机回归：1+1 easy bot 陪练、普通 2 人正式局、教学与正式房并行。
5. 破坏性边界：刷新、断线、重复消息、伪造完成、篡改 payload、清理本地存储。

## 6. 回归门槛

M0 执行前置：

- 服务端构建成功，现有 eunit 用例全过。
- `tides_sim:run(20)` 返回 `{ok,20}`；若 sim 尚未覆盖教程，会注明“正式规则门槛”，不得冒充教程覆盖。
- `node tests/robot.mjs` 输出 `SMOKE PASS`，证明正式 4 人链路无回退。
- 现有 `acceptance_checklist.md` 中已通过的 PC-09/PC-10、v0.2 人机和 v0.3 战绩/托管结论不得回退。

M0 通过门槛：

- 所有 P0 新玩家用例通过，或每个例外均有产品负责人书面豁免和风险期限。
- 正式规则回归不得出现 P0 失败；既有 P1 通过率仍不低于 `test_plan.md` 的 90%。
- 至少 1 次登录账号跨浏览器/设备状态验证，至少 1 次游客不迁移验证。
- 至少 1 次教学与普通房并行验证，至少 3 次陪练连续收束验证。
- 无服务端崩溃、数据损坏、跨身份串状态、跨房间串消息、教学计入正式数据等阻塞问题。
- 2 名无桌游经验受试者均在 10 分钟内完成首次合法行动；记录原始耗时和失败原因。

## 7. 验收标准

### 功能验收

- 新身份能从静态说明进入独立固定任务教程，再进入默认 1 真人 + 1 easy bot 陪练。
- 教程资源和任务每次可重复且固定；行动、资源变化和完成判定均由服务端权威处理。
- 教程支持跳过、退出、重玩，所有路径结果可解释且不会卡死或重复结算。
- 登录账号完成状态服务端持久化；游客完成状态仅本地保存；游客状态不自动迁移任何账号。
- 陪练使用正式规则且可正常终局；easy bot 行动合法、及时、可区分。

### 数据与隔离验收

- 教学局全过程不出现在普通房列表、普通房成员和正式行动日志中。
- 教程和陪练均不改变正式 `games`、`wins`、`ladder`、排行榜或正式局 `recent`。
- 完成、退出、重玩和重复请求均幂等；无跨账号、跨浏览器、跨房间串状态。
- 客户端无法通过修改展示状态、伪造完成消息或越权行动获得完成标记。

### 体验验收

- 页面在桌面和移动窄屏可操作，按钮状态、退出确认、加载失败和重试提示清晰。
- 新玩家无需额外口头讲解即可完成首次合法行动，目标为每人不超过 10 分钟。
- M0 不因没有奖励或复杂埋点而判定失败；只记录是否需要后续产品迭代。

## 8. 阻塞问题定义与记录

以下任一项直接阻塞 M0：

- 教程行动未经过服务端校验，或客户端可伪造固定任务完成。
- 教程能被普通玩家加入/干扰，或教学消息污染普通房间。
- 任一教学/陪练场景增加正式战绩、胜场、排行榜或正式统计。
- 登录账号完成状态丢失、账号间串用，或游客状态自动迁移到登录账号。
- 默认陪练不是 1 真人 + 1 easy bot，或 easy bot 无法合法完成整局。
- 跳过、退出、重玩任一路径导致卡死、重复结算、状态回退或资源泄漏。
- 现有正式对局 P0 回归失败、服务端崩溃或出现跨房间/跨身份数据错误。

以下通常为 P1，除非导致 P0 流程不可用：

- 文案错别字、非关键说明不完整、低概率布局溢出。
- 错误提示不够具体但仍可重试，或加载体验超过目标但流程可完成。
- 复杂埋点缺失、奖励入口未提供，符合 M0 不在范围决策。
