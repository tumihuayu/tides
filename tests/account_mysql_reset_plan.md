# 账号 / MySQL / 开发清档验收计划

本计划由测试PM维护。`account_mysql_reset_acceptance.mjs` 是无服务依赖的静态门禁：只读扫描 `server/`、`client/`、`shared/`、`deploy/`、`docs/` 和 `tests/`，不启动服务、不执行 `reset-dev`、不连接 MySQL、不删除文件。静态门禁发现缺少实现证据时必须失败，不能以“未测”冒充通过。

## 执行

```bat
node --check tests\account_mysql_reset_acceptance.mjs
node tests\account_mysql_reset_acceptance.mjs
```

脚本退出码为 `0` 仅表示所有契约均有代码/配置/文档证据；退出码为 `1` 表示仍有缺口。当前运行态用例必须在隔离开发数据库和可回滚快照上执行，禁止对共享/生产库操作。

## 静态门禁

| 编号 | 检查 | 通过标准 |
|---|---|---|
| ACC-01 | 账号注册登录 | 服务端、客户端和协议存在注册、登录、错误码、会话凭据的闭环证据 |
| ACC-02 | 游客纯客户端教程 | 游客无 role_id/PlayerProcess，不得进入任何真实对战；教程结束只能注册或退出；游客统计为零 |
| ACC-03 | 旧数据不迁移 | 明确 schema/version 策略：旧数据拒绝、隔离或备份后重建，不能静默导入 |
| ACC-04 | 同账号单房间 | 同账号并发创建/加入第二房间被拒绝，第一房间不受影响 |
| ACC-05 | 多设备登录 | 明确允许/拒绝策略；同策略下第二设备的会话、房间和数据行为可验证 |
| MYSQL-01 | MySQL 依赖 | 连接配置、健康检查、业务表清单和最小权限证据齐全 |
| MYSQL-02 | MySQL 不可用 | 模拟连接拒绝/认证失败；reset-dev 非 0 退出，不执行清档和静态资源删除 |
| MYSQL-03 | 清档后为空 | 清档完成后逐表 `COUNT(*)=0`，系统表、迁移表和非业务表不误判为业务表 |
| RST-01/02 | reset-dev 环境保护 | 仅显式 development/test 环境允许；production、缺失环境变量、拼写错误均拒绝 |
| RST-03 | 清档顺序 | 先停止服务，确认 PID/端口退出，再执行数据库清档；任一步失败立即终止 |
| RST-04 | 静态资源 | `client/dist`、上传/配置静态目录在清档前后路径、文件数和校验值不变 |

## 隔离环境运行态验收

| 编号 | 步骤 | 预期 |
|---|---|---|
| RT-01 | 注册账号 A，退出后登录 A；错误密码、重复注册、缺字段各测一次 | 成功登录返回会话；错误均为稳定错误码，不泄漏账号是否存在以外的信息 |
| RT-02 | 同 token/账号在设备 1 建房，设备 2 尝试加入或创建另一房 | 按产品策略执行；本项目若采用单房限制，第二次返回 `already_in_room`，第一房间仍可操作 |
| RT-03 | 账号 A 完成正式流程，游客完成纯客户端教程 | 游客不创建服务端玩家/房间，不产生统计；注册成功后账号数据只归属于 A/B 自身 |
| RT-04 | 备份旧版本数据库，放入开发环境后启动新版本 | 不静默迁移；按策略拒绝/隔离/重建，并保留可审计日志和原备份 |
| RT-05 | 在 development 环境执行 `reset-dev` | 先停服务；服务完全退出后清空全部业务表；静态资源仍存在且哈希不变 |
| RT-06 | 分别注入 MySQL DNS/端口不可用、账号无权限、事务中断 | reset-dev 非 0 失败关闭；不继续清理其他表、文件或静态目录；可重启服务 |
| RT-07 | 将环境设为 production、留空、`Development` 等非精确值后执行 | 全部拒绝，数据库和静态资源零变化 |
| RT-08 | 清档后查询每张业务表并重新注册/登录 | 每张业务表为 0；静态资源未删；服务可正常恢复业务 |

## 报告要求

记录版本、提交号、环境变量（敏感值打码）、服务 PID、MySQL 数据库名、业务表快照、每项退出码和静态资源校验值。任何清档失败必须附数据库和文件变更前后快照。
