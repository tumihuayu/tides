# M3 教程身份持久化、恢复与重玩执行用例

版本：M3  
状态：协议补齐并实现后执行  
维护人：测试 PM  
依据：`tests/new_player_tutorial_m2_cases.md`、`tests/new_player_test_plan.md`、`shared/protocol.md`、`docs/08_account_system_and_dev_reset_v1.0.md` 及当前 M2 实现

## 1. 分诊结论

### 1.1 M3 必做

- 登录账号的教程完成事实由服务端按不可变 `account_id` 保存；跨刷新、重登、进程重启和设备后仍可读取。
- 游客教程完成事实仅保存在当前浏览器本地；服务端不得按 `player_token`、昵称、设备或连接把游客记录升级为账号记录。
- 登录账号和游客均能在断线、自动重连及页面刷新后回到最近一次服务端确认的稳定阶段；不得恢复客户端未确认的半步结果。
- 完成后可明确发起重玩并从 T1 固定快照开始；账号既有完成事实不得被重玩、退出或重玩中断清除。
- 对缺失、损坏、过期、冲突、越权及服务不可用状态给出安全、可重试、可解释的结果。
- 补齐可测试的教程状态查询、开始/恢复、重玩及错误语义；普通房 `reconnect` 不得冒充教程恢复协议。

### 1.2 M4/M5 后续，不阻塞 M3

| 后续版本 | 内容 | M3 边界 |
|---|---|---|
| M4 | 游客主动绑定或迁移教程记录、跨浏览器游客同步、教程云存档、恢复到单个操作动画帧 | M3 明确不迁移；只恢复服务端已确认的阶段级稳定快照 |
| M4 | 多套教程、动态任务配置、按教程版本选择性重学、运营强制重置 | M3 仅验收当前固定 T1-T9；版本字段只用于兼容和审计 |
| M4 | 完成时间线、设备列表、用户自助删除教程历史 | M3 只要求完成事实可读、重玩不清除 |
| M5 | 奖励、成就、任务联动、复杂埋点、漏斗和数据看板 | M3 不发奖励、不计正式统计；缺少埋点不得阻塞 |
| M5 | 跨地域容灾、离线完成教程、客户端离线结算 | M3 所有教程行动和完成判定仍需在线服务端权威校验 |

## 2. 当前基线与协议缺口

- 当前协议已公开 `tutorial_status`、`tutorial_reconnect`、`tutorial_replay`、`tutorial_reconnected` 和 `tutorial_replay_started`，但 `start_tutorial` 仍是无 payload 的开始/恢复操作；明确重玩必须使用 `tutorial_replay`。
- 协议要求 `tutorial_state` 携带 `session_id`、`snapshot_version`、阶段和完成事实。`snapshot_version` 是会话内单调递增的稳定快照版本，新建/重玩从 1 开始；不能用客户端本地 stage 或 `tutorial_completed` 帧替代。
- 当前服务端源代码的 `reply_state/1` 和 `send_tutorial_state_map/2` 已生成 `snapshot_version`，且推进时递增；静态门禁必须同时核对这些实现事实，不能只因协议文档存在字段就判 PASS。
- 当前服务端教程进程的恢复窗口常量为 `GRACE_MS=120000`（约 120 秒）；窗口到期后 `tutorial_reconnect` 必须安全失败并要求重新开始，不能声称恢复成功。
- 当前账号完成写入通过 `tides_account:tutorial_complete/1` 按 `account_id` 更新数据库；游客不写账号完成事实。跨重启、跨设备和数据库可读性仍必须用真实账号与数据库证据验收，不能由静态源码检查判 PASS。
- 当前账号规则以 `account_id` 为业务身份，允许同账号多设备登录；旧 `player_token` 不是账号凭据或账号绑定依据。
- 当前 M2 服务端教程状态位于连接关联进程，账号表没有教程字段；客户端静态手册本地完成标记不等于固定任务教程 T1-T9 完成。

因此，执行前 `shared/protocol.md` 至少必须明确下列语义。具体消息名和字段名可由主协调裁决，但抓包中必须能无歧义观察：

| 契约编号 | 必须定义的协议语义 | 最低验收要求 |
|---|---|---|
| PC-01 | 查询当前身份教程状态 | 可区分未开始、进行中、已完成；登录账号结果来自服务端，失败不能伪装成未完成或已完成 |
| PC-02 | 开始、恢复与强制重玩意图 | 客户端明确表达 `start/resume/replay` 等价意图；不得靠先退出、断线或清本地数据猜测重玩 |
| PC-03 | 恢复点标识 | 至少能识别教程版本、当前阶段、稳定快照版本及恢复会话；恢复凭据不可伪造、不可跨身份使用 |
| PC-04 | 完成元数据 | 响应可证明 `completed=true` 属于当前账号或当前游客本地记录；账号端至少有完成版本，时间字段若提供须保持首次完成语义一致 |
| PC-05 | 错误和冲突 | 身份失效、恢复点过期、版本不兼容、并发冲突、非法重玩和存储失败均有稳定字符串 `code/reason`，且说明客户端下一步 |
| PC-06 | 消息顺序与幂等 | 明确状态快照版本/序号及请求去重规则；迟到旧快照不得覆盖新快照，重复完成/恢复/重玩不得重复结算 |

PC-01 至 PC-06 任一未进入唯一事实来源 `shared/protocol.md` 时，相关用例记为 `BLOCKED`，不得凭客户端界面或实现私有字段判 `PASS`。

## 3. 状态模型

### 3.1 双层状态

M3 必须把“完成事实”和“运行中会话”分开验收，不能用一个布尔值同时承担两者：

| 层 | 状态 | 含义 | 允许转换 |
|---|---|---|---|
| 完成事实 | `not_completed` | 当前身份尚无权威完成事实 | 合法完成 T9 后原子转为 `completed` |
| 完成事实 | `completed` | 已合法完成当前固定教程；对账号为服务端持久事实，对游客为本地事实 | 重玩、退出、断线均保持 `completed`；M3 无回退接口 |
| 运行会话 | `none` | 无可恢复教程会话 | 开始或重玩后到 `active(T1)` |
| 运行会话 | `active(Tn)` | Tn 的稳定权威快照已确认，n=1..9 | 合法行动后到下一稳定阶段；T9 后到 `finished` |
| 运行会话 | `recovering` | 已连接但身份/恢复点尚未裁决 | 成功到最近稳定 `active(Tn)`/`finished`；失败到 `none` 并返回明确错误 |
| 运行会话 | `finished` | 本轮 T9 已完成 | 可查看结果或显式 `replay` 到新的 `active(T1)` |
| 运行会话 | `exited` | 用户明确退出本轮 | 会话释放；不改变完成事实；后续按协议明确开始或恢复 |
| 运行会话 | `invalid` | 恢复点损坏、过期、版本不兼容或归属不符 | 拒绝使用；提示安全重开，不得写完成或接受旧行动 |

状态不变量：

- 只有服务端合法结算 T9 能创建账号 `completed`；客户端本地值、`tutorial_completed` 伪造帧、查询和打开结果页均不能创建它。
- 游客本地 `completed` 只控制当前浏览器的引导展示，不授权服务端跳阶段，不作为账号完成凭据。
- `completed` 与本轮 `active(Tn)` 可同时成立，表示已完成用户正在重玩。
- 每次状态推进必须原子形成一个稳定恢复点；不存在“已扣资源但仍在旧阶段”或“已显示下一阶段但恢复后重复扣费”的合法状态。
- 恢复只接受当前身份、当前教程版本和合法会话对应的恢复点；服务端仍重建并校验完整权威快照。

### 3.2 身份与存储矩阵

| 当前身份 | 完成事实来源 | 进行中恢复依据 | 刷新/同设备重启 | 跨设备 | 切换身份 |
|---|---|---|---|---|---|
| 登录账号 A | 服务端，以 `account_id=A` 归属 | 服务端账号会话/不可伪造恢复标识 | 恢复 A 最近稳定状态 | 登录 A 后读取同一完成事实；运行中恢复策略须与协议一致 | 切到 B 只读取 B，不读取 A 或游客状态 |
| 游客 G（同浏览器配置） | 本地存储 | 本地恢复提示加服务端可验证会话；本地数据不得直接推进权威阶段 | 本地数据存在且服务端恢复有效时继续；否则安全重开 | 不同步，视为新游客 | 登录 A/B 时不迁移；登出后游客本地记录仍只属于该浏览器配置 |
| 无有效登录且本地为空 | 无 | 无 | `not_completed/none` | `not_completed/none` | 登录后以账号服务端结果为准 |
| 失效/伪造 `account_session` | 不得退化为对应账号 | 不得恢复该账号教程 | 返回未认证/会话失效 | 不适用 | 明确重新登录；不能静默当该账号或迁移为游客 |
| 旧 `player_token` | 仅历史客户端标识，不是账号事实来源 | 不得据此读取账号教程 | 最多参与已明确的游客本地流程 | 不保证 | 不绑定任何账号 |

## 4. 重连时序验收

### 4.1 正常时序

1. 客户端建立 WS，不立即用本地教程状态覆盖 UI。
2. 若存在 `account_session`，先完成账号会话校验；校验成功后才查询/恢复该 `account_id` 的教程状态。游客则只读取当前浏览器本地记录。
3. 客户端携协议规定的恢复意图和恢复凭据请求恢复；不得发送普通房 `reconnect`。
4. 服务端校验身份、教程版本、会话归属、有效期和并发状态。
5. 服务端先返回恢复裁决，再返回一个完整的最新权威 `tutorial_state`；客户端按快照版本/序号丢弃迟到旧状态。
6. 只有完整快照应用成功后才解除恢复遮罩并允许行动；恢复期间点击和旧页面重放不能提交有效新行动。

### 4.2 未确认行动的裁决

- 已发送但断线前未收到 `tutorial_ack` 时，重连后以服务端持久/会话去重记录和最新权威快照为准。
- 若服务端已结算，恢复到结算后的阶段，重发相同 `action_id` 只得到等价确认，不再次结算。
- 若服务端未结算，恢复到行动前稳定快照；客户端可在明确恢复完成后重试，不能仅凭本地乐观状态显示成功。
- 无论消息先后顺序如何，同一行动最多结算一次，阶段和恢复点版本只能前进不能回退。

## 5. M3 执行用例

每条用例均须记录客户端构建、服务端版本、协议版本、脱敏身份、原始 WS 帧、状态版本、数据库或服务端查询证据、本地存储前后值及日志路径。仅看到 UI 文案不能证明服务端持久化、幂等或隔离。

### 5.1 协议与状态可观测性（6 条）

| ID | 优先级 | 前置与步骤 | 预期 |
|---|---|---|---|
| M3-P01 | P0 | 新账号 A 查询教程状态，再开始教程 | 查询明确为未完成/无会话；开始返回 T1 完整权威快照及可识别恢复版本，不创建普通房 |
| M3-P02 | P0 | A 推进到 T4 后再次查询/恢复 | 能区分 `not_completed` 与 `active(T4)`；完成事实和运行会话不是同一布尔值 |
| M3-P03 | P0 | 分别明确请求继续和从头重玩 | 继续恢复最近稳定阶段；重玩创建新一轮 T1；服务端可无歧义区分两种意图 |
| M3-P04 | P0 | 合法完成 T9，记录最后行动的 ack、state、completed 和查询响应顺序 | 协议顺序可解释且最终查询为 completed；丢包/乱序下不能短暂回退未完成或重复完成 |
| M3-P05 | P0 | 提交过期、损坏、错误版本和他人恢复凭据 | 返回稳定字符串错误码/原因及可执行后续动作；不泄漏快照、不推进、不崩溃 |
| M3-P06 | P0 | 抓取账号 A、游客 G 的全部教程帧 | 响应足以判断身份语义但不暴露密码、完整账号会话、数据库键或可被他人使用的秘密；private_state 仅本人连接可见 |

### 5.2 身份、持久化与数据隔离（10 条）

| ID | 优先级 | 前置与步骤 | 预期 |
|---|---|---|---|
| M3-I01 | P0 | A 完成后刷新、登出、重新登录 A，并清空浏览器全部本地存储 | A 仍为 completed，依据为服务端账号记录；首次完成版本/时间若提供不得被普通读取改写 |
| M3-I02 | P0 | 设备 1 完成 A；设备 2 登录 A 查询 | 两设备读取同一完成事实，不依赖设备 1 本地数据或 `player_token` |
| M3-I03 | P0 | A 完成后重启服务端及账号服务，再登录查询 | 完成事实仍存在；只存在 ETS/教程进程或客户端缓存不能判通过 |
| M3-I04 | P0 | A 完成；依次登录未完成 B、已完成 C | B 为未完成，C 保持自身完成元数据；A/B/C 无覆盖、合并或串读 |
| M3-I05 | P0 | 游客 G 完成，刷新和关闭后重开同一浏览器配置 | 本地记录有效时显示游客已完成；没有账号教程写入，服务端重启不被宣称保存游客完成事实 |
| M3-I06 | P0 | G 完成后清除教程本地键，再重开 | 游客回到未完成；应用不崩溃，任何账号完成事实不受影响 |
| M3-I07 | P0 | G 完成后登录未完成 B | B 仍未完成；不得按昵称、`player_token`、设备或本地 completed 自动迁移 |
| M3-I08 | P0 | G 完成后登录已完成 A，再登出回游客 | 登录时只展示 A 的服务端状态且不改 A 元数据；登出后恢复当前浏览器的游客本地状态，二者不合并 |
| M3-I09 | P0 | 同一浏览器先后登录 A/B，各自推进或完成，再清存储重登 | 每个账号只读写自己的 `account_id` 记录；本地缓存键不能导致最后登录账号污染前一账号 |
| M3-I10 | P0 | 携旧 `player_token`、伪造昵称或复制 A 的非登录本地数据，以游客/B 查询 | 不能读取、恢复或更改 A 的教程完成和 private_state；旧 token 不成为账号绑定依据 |

### 5.3 断线、刷新与恢复（8 条）

| ID | 优先级 | 前置与步骤 | 预期 |
|---|---|---|---|
| M3-R01 | P0 | A 在 T4 收到 `tutorial_state(session_id, snapshot_version=v)` 后断开并在 120 秒恢复窗口内刷新页面，发送 `tutorial_reconnect` | 先收到 `tutorial_reconnected`，随后完整状态仍为 T4 且 `snapshot_version >= v`；无 T1 闪现造成可操作窗口，无重复扣费或正式数据变化 |
| M3-R02 | P0 | 游客 G 在 T4 收到完整状态后刷新，保留本地数据 | 服务端验证恢复依据后恢复 T4；本地阶段值本身不能让服务端跳到 T4 |
| M3-R03 | P0 | A/G 在合法行动发出、ack 前强制断网，覆盖“服务端未结算”和“已结算但响应丢失”两支 | 分别恢复行动前或行动后唯一稳定快照；相同 `action_id` 重试最多结算一次 |
| M3-R04 | P0 | 在收到 ack 后、下一 `tutorial_state` 前断线 | 恢复到 ack 对应的结算后状态；不能重复行动，也不能永久停在加载页 |
| M3-R05 | P0 | T9 请求发出后分别在 ack/completed 前断线并恢复 | 最终完成事实恰好一次；恢复后能得到 completed 终态，不重复正式统计或奖励 |
| M3-R06 | P0 | 自动重连期间连续刷新、开两个标签并反复触发恢复 | 只有一个单调权威进度；旧快照和迟到帧被丢弃，无双推进、回退或孤儿教程进程 |
| M3-R07 | P0 | 分别在 120 秒恢复窗口外、服务端释放会话后，及使用损坏/不兼容版本凭据恢复 | 返回字符串 `code`/`message`，明确安全从 T1 重开；不信任本地资源，不误标完成，不影响既有账号 completed；窗口内才允许恢复 |
| M3-R08 | P1 | 在高延迟、乱序、短时断网和多次指数退避下从 T1 完成一轮 | 恢复遮罩期间禁止有效重复操作；网络恢复后可继续，状态版本单调且无消息风暴 |

### 5.4 完成后重玩（4 条）

| ID | 优先级 | 前置与步骤 | 预期 |
|---|---|---|---|
| M3-W01 | P0 | `tutorial_status.completed=true` 的 A 显式发送 `tutorial_replay`，保存旧 session_id/version 与新帧 | 收到 `tutorial_replay_started` 的新 `session_id`，随后 T1 完整快照且新 `snapshot_version=1`；账号完成事实仍为 completed；不是恢复 finished/T9 |
| M3-W02 | P0 | A 重玩到 T3 后退出、刷新、重登 | 首次完成事实保持；运行会话按协议恢复 T3 或明确退出后重开，不能把账号降为未完成 |
| M3-W03 | P0 | completed 的游客 G 重玩到 T3，再刷新和清除本地记录分别验证 | 保留本地时完成展示与重玩会话可并存；清除后不再宣称游客完成，且不能凭本地 T3 伪造服务端进度 |
| M3-W04 | P0 | 连续点击重玩、重复同一重玩请求，并在 A 两设备同时重玩；记录每次请求及 session_id | 每个幂等请求只创建一轮；最终只有一套权威进度，无多教程进程、完成时间改写、重复统计或奖励；若当前协议没有 replay 去重标识，必须记为 BLOCKED/FAIL，不得推断幂等 |

### 5.5 异常、并发、幂等与安全（8 条）

| ID | 优先级 | 前置与步骤 | 预期 |
|---|---|---|---|
| M3-A01 | P0 | 账号教程状态数据库读取超时、不可用或返回异常 | 明确加载失败/可重试；不能当未完成自动开新轮，不能当已完成放行，也不能用游客本地值覆盖账号事实 |

## 6. 数据与安全检查

### 6.1 账号服务端数据

- 以脱敏 `account_id` 核对持久记录，不以账号名、昵称、连接 PID、房间 token 或旧 `player_token` 作为归属键。
- 完成写入必须具备数据库级原子性和重复写安全；服务端重启后可读，缓存丢失不影响事实。
- 日志不得含密码、密码哈希、完整 `account_session`、可复用恢复秘密或完整 private_state。
- 账号 A 的查询、恢复、错误码和耗时差异不得向未认证连接暴露 A 的完成状态或存在性。
- 教程完成记录属于开发清档的业务数据范围；清档后账号本身若也按既有规则清除，不得残留孤儿教程记录。

### 6.2 游客本地数据

- 本地键须与静态手册完成标记、账号会话缓存明确区分；不能把“读完静态说明”当作“T1-T9 完成”。
- 本地内容视为不可信输入，损坏和篡改只能影响游客入口展示，不能授权服务端行动、恢复他人会话或创建账号完成事实。
- 登入账号时账号服务端状态优先且隔离；不得上传、合并或删除游客记录。登出后的游客展示按当前浏览器本地记录重新判断。
- 浏览器配置、隐私模式和不同源存储天然隔离；M3 不承诺游客跨设备或跨浏览器同步。

## 7. 回归门槛与阻塞标准

### 7.1 执行前置门槛

- PC-01 至 PC-06 已写入 `shared/protocol.md`，客户端、服务端和测试使用同一协议版本。
- 服务端构建成功，现有 eunit 全过，`tides_sim:run(20)` 返回 `{ok,20}`。
- `node tests/robot.mjs` 输出 `SMOKE PASS`；客户端正式构建成功。
- 有可清理的 A/B/C 账号、两个独立浏览器/设备环境、游客环境、数据库只读核对方式，以及可注入断网、延迟、存储失败和账号服务失败的测试环境。
- M2-T01 至 M2-T24 至少先完成 P0 冒烟；M2 已知协议缺口须由 M3 契约关闭，不能继续豁免后宣称 M3 通过。

### 7.2 M3 通过门槛

- 本文件 40 条用例中，39 条 P0 必须全部通过；M3-R08 为 P1，须执行且不得发现状态损坏、安全或身份隔离问题。
- 至少完成 1 次账号跨服务端重启、1 次账号跨设备、1 次游客同浏览器重启、1 次游客清存储和 1 次游客登录账号不迁移的证据链。
- 未确认行动必须覆盖“服务端未结算”和“服务端已结算但响应丢失”两支；T9 断线必须覆盖 ack/completed 丢失。
- 同账号双设备并发推进和并发重玩各连续执行至少 10 轮，无分叉、双结算和孤儿会话。
- 教程完成、恢复、重玩全过程不得改变正式统计；M2 固定快照、权威校验、隐私和普通房冒烟不得回退。

### 7.3 直接阻塞 M3 的问题

以下任一项出现即判 `FAIL` 并阻塞 M3；若因协议或环境不可执行则判 `BLOCKED`，同样不得发布为 M3 已验收：

- PC-01 至 PC-06 任一未定义，导致查询、恢复、重玩、错误或幂等无法通过公开协议验收。
- 登录账号完成事实未落服务端持久库，服务端重启/换设备后丢失，或能被重玩、退出、刷新降级。
- 游客完成记录写入账号服务、自动迁移到账号，或旧 `player_token`/昵称可绑定、读取账号状态。
- 任意跨账号、跨游客、跨连接的教程进度、完成事实、恢复凭据或 private_state 串用/泄漏。
- 刷新/断线造成阶段回退、跳阶段、重复扣费、重复完成、双会话分叉、永久卡死或客户端未确认状态被当作权威。
- 客户端篡改、伪造完成、复制恢复凭据或重放请求可创建完成事实、越权恢复或绕过服务端行动校验。
- 完成持久化失败后仍向客户端确认成功，或数据库出现半写、重复副作用、不可恢复损坏。
- 完成后不能重玩，重玩不是从 T1 固定快照开始，或重玩清除/改写既有完成事实。
- 教程进入普通房列表/消息，污染正式战绩、排行榜、奖励，或导致既有正式对局 P0 回归失败。
- 服务端崩溃、账号服务雪崩、敏感凭据进入响应/日志，或异常本地数据导致客户端不可恢复崩溃。

通常不阻塞 M3：不影响操作的文案细节、M4/M5 明确后续项、非关键动画未恢复、缺少奖励或复杂埋点。若其实际导致身份误判、无法恢复或 P0 主流程不可用，则升级为阻塞。
