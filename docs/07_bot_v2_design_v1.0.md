## 1. 功能定位

- Bot v2 的难度、记牌和托管状态均属于房间临时数据；Bot 不创建 `#role`、`role_id` 或长期档案，房间关闭即销毁。
- 普通账号 + Bot 的正式规则局按既定规则统计并归属该账号 `role_id`；Bot、游客、教程和 `practice` 不产生正式统计。

- **难度分级**：现有启发式人机升级为「简单」，新增「困难」档，让老玩家有可对抗的对手。
- **真人掉线托管**：真人断线超过 grace（60s）后由简单人机接管其回合，重连后夺回控制权。解决 v1 遗留痛点：掉线玩家「自动弃牌第1张 tide」形同挂机，拖累整局体验。
- **非目标（本期不做）**：人机聊天/表情、人格可视化、练习模式、机器学习/搜索类 AI（MCTS 等）。

## 2. 难度分级

### 2.1 档位定义

| 档位 | difficulty | 定义 |
|---|---|---|
| 简单 | `easy` | v1 现有启发式全套（优先级评估 + 人格 + 15% 扰动），**随机扰动提升至 30%**，并额外有 15% 概率在合法候选中纯随机选择。定位为新手陪练 |
| 困难 | `hard` | v1 启发式为底，扰动降为 5%，叠加 §2.2 全部增强点。定位为可击败老玩家 |

- 大厅添加人机时由房主选择难度（默认简单）。
- 困难人机每房间**不限数量**，但推荐 UI 文案提示「困难人机很强，建议从1台开始」。

### 2.2 困难档具体增强点

在 v1 §3.1 决策框架之上叠加（全部只使用公开信息 + 自身私有信息，信息边界与真人一致）：

1. **记牌（公开信息推算）**
   - 维护「已亮出牌/弃牌堆」计数：每种行动卡（sail/trade/deliver/post/tidecraft/tailwind）已出现张数，结合牌库总量推算剩余分布。用于：
     - 估算对手手中大概率持有的行动类型（例如 post 卡已出 3 张则商站竞争威胁下降，自己设站权重提高）；
     - deliver 卡剩余稀少时，囤货权重下降、卖货权重上升。
   - 记录**每张已亮 tide 弃牌的潮纹值**，推算对手手牌的平均潮纹倾向，预测本回合潮汐推进方向（多数派会推高潮还是压低潮）。
2. **针对性卡位**
   - **商站卡位**：识别某港口当前商站领先者（终局将拿 4 分），若自己无法超越且该玩家是主要竞争对手（当前估算总分接近自己），则**不在该港投入**，转而抢占第二名的 2 分港口；反之若自己领先，计算对手追平所需投入，决定是否在关键港补第 2/3 个商站拉开差距。
   - **压价干扰**：对手船在某港且货仓接近满仓时，若自己卖货会压低其欲售货物市价，且对手预计下回合卖该货 → 抢先在更低价位卖出（价格破坏），权重中等。
   - **潮汐狙击**：终局前两回合，若预测对手将交付涨潮 +1VP 订单，且自己 tide 弃牌能使潮位在对手行动前离开 rising → 主动打高/低潮纹卡改变潮序（向不利对手方向推潮）。
3. **终局抢分策略**
   - 最后一轮（round=4）切换评估函数：每个候选行动直接估算「终局总分增量」（订单 VP + 商站名次分 + 留货分 min(cargo,5) + 金币分 min(coins/3,4)），取期望值最高者，替代常规优先级表。
   - 终局放弃长线投资：round ≥ 3 后 post（商站）仅当能改变名次才执行；round=4 不再买非即交货物。
   - 隐藏订单清算：round=4 优先交付隐藏订单（ebb +1VP 窗口），避免烂在手里。
4. **前瞻 1 回合潮汐落点**：综合本回合自己弃牌 + 预测对手弃牌潮纹，计算下回合潮位，提前规划 sail 费用（满潮 -1）与交货时机（rising +1VP）。

### 2.3 实现提示（供后端参考）

- 决策模块按 `difficulty` 分发：`easy` → v1 逻辑 + 高扰动参数；`hard` → v1 逻辑 + 增强模块 + 低扰动。共用合法性兜底（非法提交回退 auto_submit）。
- 记牌/对手建模的状态挂在 bot 实例上，随房间销毁，不落库。
- 困难人机单回合决策耗时须 < 200ms（纯启发式，无搜索），超时也走兜底。

## 3. 真人掉线托管（auto-pilot）

### 3.1 规则

1. 真人断线后沿用现有 grace（`reconnect_grace_ms`=60s）：grace 内仍走 v1「超时自动弃第1张 tide」。
2. **grace 到期未重连** → 该座位进入托管：由**简单人机**（v1 启发式，含人格随机）接管其后续所有 select 提交；身份仍是原玩家（名字、分数、战绩归属不变）。
3. **重连夺回控制权**：`reconnect` 成功后托管立即解除，下一 select 阶段起由真人操作；正在执行的人机延迟提交若已发出则该回合有效（不撤回）。
4. 托管状态全员可见：`public_state.players[]` 与 `room_update` 的 PlayerBrief 增加 `auto_pilot=true` 字段；终局结算页对托管完成的对局在昵称旁标注「（托管完成）」。
5. 托管玩家正常参与结算与战绩计分（与 03 策划案 §7「30 秒后掉线正常计分」一致）。
6. 房主掉线被托管时，房主身份规则不变（游戏阶段不转移）。

### 3.2 与现有超时的关系

- 托管是对「grace 到期后继续走超时自动行动」的**升级替换**，不改变 grace 内的行为，不改变 45s select 超时机制（人机托管提交若失败仍走 auto_submit 兜底）。
- lobby 阶段不涉及托管（掉线房主转移/房间解散规则不变）。

## 4. 协议变更提案（供主协调修改 shared/protocol.md）

### 4.1 `add_bot` 增加 difficulty

```json
{"type":"add_bot","room_id":"A7Q2","player_id":"p1","player_token":"...","action_id":"f47ac10b","seq":7,"ts":1730000100,"payload":{"difficulty":"hard"}}
```

- `difficulty`: `"easy"|"hard"`，省略时默认 `"easy"`。
- 新错误码：`invalid_difficulty`。

### 4.2 PlayerBrief / public_state.players[] 扩展

```json
{"id":"bot_2","name":"洛满仓","ready":true,"host":false,"connected":true,"is_bot":true,"difficulty":"hard","auto_pilot":false}
```

| 字段 | 位置 | 说明 |
|---|---|---|
| `difficulty` | PlayerBrief + public_state.players[] | 仅 `is_bot=true` 时有值（`"easy"|"hard"`）；真人为 null 或省略 |
| `auto_pilot` | PlayerBrief + public_state.players[] | 真人被托管时为 true；其余情况 false |

### 4.3 托管状态变更广播

托管进入/解除时复用 `room_update`（lobby 外也广播，仅含 players 列表）即可，**不新增消息类型**；前端依据 `auto_pilot` 字段刷新显示。

### 4.4 不变更项

- `remove_bot` 不变；游戏中不可增删人机（含不可改难度）。
- 人机 ID/命名池/房主转移规则不变（沿用 v1）。

## 5. 体验细节

| 项 | 设计 |
|---|---|
| 托管提示文案 | 全员 action_log 播报：「XX 已离线超过60秒，由托管代打」；重连时：「XX 已回到牌桌」。被托管者本人重连后弹 toast：「离线期间由托管代打，欢迎回来」 |
| 难度徽标 | 大厅与游戏内：简单=「(人机·简单)」灰色徽标；困难=「(人机·困难)」金色徽标；前端按 `difficulty` 渲染，不写入 name |
| 思考延迟 | 简单人机保持 1-3s 均匀随机；**困难人机 2-4s**（更慢，强化「在认真算」的观感，同时掩盖更复杂的计算）；托管人机固定 1-2s（避免被托管者重连时等待感过长） |
| 终局展示 | 结算页人机名字旁显示难度徽标；托管完成的真人标注「（托管完成）」 |
| 战绩联动 | 普通账号 + Bot 正式规则局按既定规则正常计分，`has_bot=true`；托管完成的真人仍归属其 `role_id`；Bot、游客、教程和 `practice` 不统计 |

## 附：验收清单（供测试PM）

1. `add_bot {difficulty:"hard"}` 成功，`room_update` 与 `public_state.players[]` 中 `difficulty="hard"`；省略时默认 `easy`；非法值返回 `invalid_difficulty`。
2. 简单人机扰动明显（统计上 30% 跳过优先选项），困难人机在固定种子测试中终局得分显著高于简单人机（自玩模拟 20 局均值对比）。
3. 困难人机思考延迟 2-4s；简单 1-3s；超时兜底 45s 对两档均生效。
4. 真人断线 60s 后：`public_state.players[].auto_pilot=true` 广播，托管人机在 1-2s 内正常提交合法行动（非恒弃第1张 tide）；`action_log` 出现托管播报。
5. 被托管者 `reconnect` 成功：auto_pilot 恢复 false，下一 select 可正常 `submit_card`。
6. 托管玩家正常进入 `game_over` 计分，并按其 `role_id` 进行正式战绩结算；Bot 不建档。
7. 人机互打局（1真人托管+3人机）能正常打完 12 回合。
8. 混合难度房（1 easy + 1 hard）正常开局、结算。

## 6. 废止旧规则

- 废止“含人机局 ladder_delta 减半”的旧规则，及以 `player_token` 判断或归属统计的旧方案。
- 托管不改变真人账号的 `role_id` 归属；房间关闭后托管/Bot 运行态一并销毁。
