# 《潮汐商会》UI 规格 v1.0

> 依据：shared/protocol.md v0.1。颜色语义遵循 04_art_direction.md §2。
> 阶段模型：`select`（选牌）→ `resolve`（结算）→ `game_over`（终局），由服务端 `phase_changed` 驱动。

## 1. 界面清单

| # | 界面 | 说明 |
|---|---|---|
| S1 | 登录/起名 | 输入玩家名，创建或加入房间 |
| S2 | 大厅（房间） | 房间号、4 个席位、准备状态、房主开局按钮 |
| S3 | 对局主界面 | 核心界面，见 §2 |
| S4 | 行动目标选择浮层 | submit_card 的 target 录入（港口/货物/订单/秘术操作） |
| S5 | 结算回放条 | resolve 阶段按座位顺序逐条播放行动日志 |
| S6 | 终局计分板 | game_over 的 breakdown 逐项展示 |
| S7 | 断线重连提示层 | 全屏遮罩，倒计时与重连状态 |

## 2. 对局主界面（S3）布局分区

桌面端 16:9 基准，自上而下、自中向外：

```
┌──────────────────────────────────────────────────────────┐
│ A 顶部状态条：回合 2-1/4-3 · 阶段 · 倒计时 · 连接状态     │
├──────────┬───────────────────────────────┬───────────────┤
│ B 潮汐区  │        C 中央港口海图          │  D 市场区      │
│ 轨道4格   │   4 港环形排布，各港显示：      │  3 条价格轨    │
│ 当前档    │   船位标记/商站桩位/相邻航路    │  salt/lamp/silk│
│ 事件预告  │                               │  1-6 刻度      │
├──────────┴───────────────────────────────┴───────────────┤
│ E 公开订单区（3 张横排，显示需求/奖励/已被抢注状态）        │
├──────────────────────────────────────────────────────────┤
│ F 对手信息带：每人一格——名字/金币/VP/货仓数/已提交✓/在线   │
├──────────────────────────────────────────────────────────┤
│ G 本人区：金币 · VP · 货仓明细 · 隐藏订单 · 手牌(扇形)      │
│    手牌选中后浮出三用途按钮：[行动] [存货] [推潮]           │
└──────────────────────────────────────────────────────────┘
```

### 分区职责
- **A 状态条**：`round/turn/phase/deadline_ts`；倒计时 ≤10s 变礁红并脉冲。
- **B 潮汐区**：潮汐轨道四档用潮位状态色（§4.2 美术规范）；本回合已累积的推进值以「+N」气泡显示；当前档效果用一行简注常驻（如「满潮：航行免费·卖货+1」）。
- **C 海图**：玩家当前所在港高亮描边；可航行到的相邻港在扬帆目标选择时点亮；各港商站以桩位槽阵列展示，多数领先者旗标放大。
- **D 市场区**：每条价格轨显示当前价（大数字）+ 本回合变动方向箭头（青▲/红▼）；钳制到 1 或 6 时该端刻度变灰。
- **F 对手信息带**：只显示 public_state 字段（金币/VP/cargo_count/submitted/connected），**货仓仅显示数量不显示明细**；断线者置灰并叠加断线图标。
- **G 本人区**：手牌按行动角标+货物徽章双编码；隐藏订单卡片带「密」角标，仅本人可展开。

## 3. 交互流程（核心五拍）

**选牌 → 用途 → 目标 → 确认 → 等待**

1. **选牌**：select 阶段点击手牌，卡牌上浮，其余牌半透明。
2. **用途**：浮出三按钮——
   - `[行动]`：显示该卡行动名的完整描述（如「扬帆：支付航行费，移至相邻港」）；
   - `[存货]`：显示货物徽章（「留存为 灯油」）；
   - `[推潮]`：显示潮纹（「推进潮汐 1 格」，wild 显示「潮纹 0：不推进」）。
3. **目标**：选 `行动` 时按行动类型弹 S4 浮层：
   - sail：海图上相邻港点亮，点选；
   - trade：选 买/卖 → 选货物 → 买时选数量 1-2（步进器，实时显示总价与受潮汐修正后的单价）；
   - deliver：列出当前可交付订单（可交付=货仓满足的置亮，不满足的灰显并标注缺货）；
   - post：固定为当前港，显示设站费 2 金与现有商站；
   - tidecraft：选 窥探/推移（+1/-1）；
   - tailwind：先点海图相邻港，再选交易参数（两段式）。
   - 用途为 `存货`/`推潮` 时跳过本步。
4. **确认**：摘要条复述完整决策（「顺风 → 雾门 → 卖出 丝贝×1」）+ `[确认提交]`。提交即锁定（服务端 `ack` 后手牌区该卡标记已提交）；收到 `action_rejected` 时解除锁定并 Toast 原因。
5. **等待**：本人格显示「已提交 ✓」，F 区实时更新他人 submitted 状态；全员提交或倒计时归零后进入结算回放（S5），随后 `state_sync` 刷新全部分区。

## 4. 信息层级与颜色语义

### 4.1 信息层级（视觉权重从高到低）
1. **本回合待办**：倒计时、待提交提示（汐金高亮）。
2. **状态突变**：潮汐档位、价格变动、本人金币/VP 增减（数字滚动+箭头动效）。
3. **常驻状态**：市场三价、潮位、回合数。
4. **背景信息**：他人明细、日志历史（默认折叠）。
5. **私密信息**：手牌、隐藏订单（带「仅你可见」标识，防止直播/截屏误解）。

### 4.2 颜色语义（全局一致，不得另立含义）
| 语义 | 颜色 |
|---|---|
| 可交互/推荐操作 | 汐金 `#D9A441` |
| 获得（金币/VP/提价） | 涨潮青 `#4FA3A5` |
| 损失（扣金/压价/错误） | 礁红 `#B5503C` |
| 中性信息/不可交互 | 雾白 `#E8E4D8`（降透明度） |
| 潮位四态 | 滩涂褐/涨潮青/满月银蓝/暮潮紫灰 |
| 断线/失效 | 整体置灰 + 斜纹 |

## 5. 空态 / 断线 / 错误提示文案

### 5.1 空态
| 场景 | 文案 |
|---|---|
| 大厅等人 | 「潮还未涨。把房间号告诉其他船长吧（2-4 人开局）。」 |
| 公开订单被抢完 | 「公开订单已全部交付。风向变了——看看你手里的密单。」 |
| 货仓为空 | 「船舱空空。用 [存货] 用途留一手货，或去市集买两件。」 |
| 手牌为空 | 「无牌可打，静候本局结束结算。」 |
| 日志为空 | 「海雾未散，尚无动静。」 |

### 5.2 断线与重连
| 场景 | 文案 |
|---|---|
| 自己断线 | 「与灯塔失去联系……正在重连（剩余 60 秒）。重连期间将按超时规则自动代打。」 |
| 重连成功 | 「重新望见灯塔。已同步最新局面。」 |
| 重连失败/超时 | 「本次航行已无法归队，可返回大厅重新开局。」 |
| 他人断线（F 区徽标 tooltip） | 「该船长暂时失联，超时将由系统代打，不阻塞对局。」 |

### 5.3 错误提示（action_rejected 的 reason 直出 + 兜底）
| 场景 | 文案模板 |
|---|---|
| 费用不足 | 「金币不够：需要 {cost}，你只有 {coins}。」 |
| 目标港不相邻 | 「{port} 不在当前航路上，只能驶往相邻港口。」 |
| 货仓缺货 | 「舱里没有足够的 {good}。」 |
| 订单不满足 | 「这张订单还差：{missing}。」 |
| 阶段不符 | 「现在不是选牌阶段，请等待结算完成。」 |
| 重复提交 | 「已收到你的决策，无需重复提交。」 |
| 兜底 | 「操作未被接受：{reason}」 |

### 5.4 超时提示
- 倒计时 ≤10s：「潮不等人！{n} 秒后将自动打出第 1 张手牌推潮。」
- 触发自动代打后：「超时：系统已将「{card_name}」以推潮打出。」
