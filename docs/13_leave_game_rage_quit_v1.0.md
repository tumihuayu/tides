# 《潮汐商会》对战中退出对战（退出者判负）策划案 v1.0

> 依据：测试PM 分诊结论（已定技术方案）、docs/06_stats_leaderboard_v1.0.md、docs/07_bot_v2_design_v1.0.md、docs/12_battle_settlement_v1.0.md、shared/protocol.md。
> 本文冻结「对战中主动退出」全部规则口径；实现与测试以本文为准。`shared/` 由主协调统一修改，本文只提协议提案（见 §6）。
> **与 docs/06 的关系**：本文取代 docs/06 §7「秒退处理」中「开局 30 秒内主动退出按末名计」的旧口径，扩展为「任意时刻主动退出均判末名」；docs/06 的天梯计分表、统计归属、其余反刷分措施继续有效。冲突处以本文为准。

---

## 1. 功能定位

给对战中「不想打了」的玩家一个明确、可控的退出出口：点一下就能走，回大厅立刻开下一局；同时让留下的玩家不受拖累（AI 托管代打，对局不中断），退出者付出明确代价（强制末名 + 天梯扣分 + 连胜清零），防止用「秒退」逃避败局。

- **设计意图**：降低中途退出的摩擦成本（硬等打完或关页面挂机都伤害体验），用「判负」而非「禁止」管理行为，口径一行可向玩家解释清楚（「主动退出 = 直接判最后一名」）。
- **非目标（本期不做）**：大厅阶段（未开局）退出规则调整、退出惩罚梯度/封号、逃跑率统计展示、重连回原对局。

## 2. 冻结口径

### 2.1 主动退出的定义与入口

- **入口**：对战进行中（游戏开局后、终局结算前）的对局内 UI 提供「退出对战」按钮，点击后**二次确认**（确认文案需明示「退出将判为最后一名」）。
- **生效范围**：仅对战中；大厅/房间准备阶段的离开沿用既有离开房间逻辑，**不在本次范围**。
- **不算主动退出**：刷新页面、关闭页面、网络断连均**不触发** leave_game，走既有断线流程（断线 grace 60s 内可重连，grace 到期由 AI 托管，见 docs/07）。
- 玩家点击确认后发送 `leave_game` 请求；服务端确认后**立即返回大厅**，其座位由 auto_pilot 托管打完本局。

### 2.2 退出判负细则

- **强制末名**：主动退出者无论何时退出（任意时刻），结算时**强制排名末名**，不参与按总分的正常排名；其名次由剩余玩家正常排。
- **天梯分**：得末名对应天梯分（2人局 **-10** / 3人局 **-15** / 4人局 **-20**，即 docs/06 §2.2 计分表末名档）；天梯下限 0 的新手保护照常生效。
- **连胜清零**：强制末名即 `rank > 1`，按 docs/12 §2.3 口径 `win_streak = 0`，打断连胜。
- **统计计入**：本局正常计入正式统计档案——`games + 1`，`wins` 不变（不增）；recent 记录照常写入。
- **rage_quit 语义扩展**：`rage_quit` 从「开局 30s 内断线」扩展为「**任意时刻主动退出**，或断线 30s 内 grace 到期未归」。即主动退出不再受 30s 窗口限制，任意时刻均判末名；**30s 窗口仅保留给断线场景**（断线 30s 内未归按末名，超过 30s 后掉线未归仍走托管按实际总分正常排名，见 docs/06 §7「中途弃局」）。
- 其余在场玩家：对局不中断，正常打完，按实际总分正常排名结算（末名被退出者占走，剩余玩家按总分排其余名次）。

### 2.3 托管代打规则

- 退出者座位由 **auto_pilot**（托管人机，docs/07 v2 同款）接管，正常提交合法行动，对局不中断、不阻塞其他玩家。
- `public_state.players[].auto_pilot=true` 广播；该玩家 `connected=false`，对手信息带按断线者置灰展示（docs/05 F 区规则）。
- 托管只负责「把本局打完」，不改变 2.2 的判负口径：退出者结算时强制末名，与托管打出的实际总分无关。

### 2.4 边界规则

| 场景 | 裁决 |
|---|---|
| 对局已结束后退出 | `leave_game` 无效；对局已按正常结算落盘，退出者按实际名次计，不追加强制末名 |
| 多人同时退出 | 各退出者**并列末名**，均得末名天梯分（并列名次取均分、向下取整，沿用 docs/06 §2.2 并列规则）；剩余玩家正常排名 |
| 刷新/关闭页面 | **不算**主动退出，走断线流程（60s grace 内可重连恢复；grace 到期 AI 托管，按断线口径结算） |
| 退出后开新局 | 退出者账号房间占用立即释放，**可立即创建/加入新房间** |
| 重连回原房间 | `reconnect` 回原房间**被拒**（座位已视为放弃，由 auto_pilot 打完）；报错码回大厅 |
| 断线 vs 主动退出 | 主动退出（leave_game）= 任意时刻强制末名；断线 = grace 内可重连，30s 窗口内未归按末名、超 30s 托管按实际排名（docs/06 §7） |

## 3. 与其他文档的关系

- **docs/06 §7「秒退处理」**：旧口径「开局 30 秒内退出/掉线且 grace 到期未归按末名」中，**主动退出部分由本文取代**（任意时刻退出均判末名，不再限于 30s）；断线部分（30s 窗口）继续有效。06 §7 表格已同步修订并指向本文。
- **docs/07（托管人机 v2）**：托管代打能力复用 v2 auto_pilot，本文不重复设计托管 AI 行为。
- **docs/12（战斗结算）**：§2.1/§2.3/§5.3 的 rage_quit 判负、连胜清零口径与本文一致，「秒退玩家」表述扩展为「主动退出/秒退玩家」，展示规则不变（在场者正常看到「失败」结算页；已退出者看不到结算页属正常，数据已落盘，个人中心可查）。

## 5. 验收要点（供测试PM）

1. 对战中点「退出对战」→ 二次确认 → 发 leave_game → 立即回大厅；原房间对局继续，退出者 `auto_pilot=true`、`connected=false`。
2. 退出者结算强制末名，天梯按末名档扣（2/3/4 人局 -10/-15/-20，下限 0），`win_streak` 清零，`games+1`、`wins` 不变。
3. 剩余玩家按总分正常排名结算，不受退出影响。
4. 对局结束后发 leave_game 无效；多人同时退出并列末名。
5. 刷新/关闭页面不触发 leave_game，走断线重连流程；60s 内可重连恢复。
6. 退出后立即可创建/加入新房间；reconnect 回原房间被拒。
7. 开局 30s 内与 30s 后主动退出均判末名（验证 30s 窗口不再限制主动退出）。

## 6. 协议提案（移交主协调，shared/protocol.md）

1. 新增客户端→服务端消息 **`leave_game`**：对战中请求主动退出；服务端校验对局进行中、发送者为在场真人，确认后执行判负流程并释放房间占用。错误码建议：`game_not_started`、`already_game_over`（对局已结束退出无效）、`not_in_game`。
2. 新增服务端→客户端广播 **`player_left`**：`{player_id, reason}`，`reason` 枚举建议 `"quit"`（主动退出）/ `"disconnect"`（断线），用于 UI 区分「已弃船判末名」与「暂时失联可重连」；主动退出者同时置 `auto_pilot=true`、`connected=false`。
3. **`game_over.scores[]`**：退出者 `rank` 为末名（多人退出并列末名），`ladder_delta` 为末名档；建议 `game_over` 或 scores 项增加 `reason`/`rage_quit` 标记，并写明 rage_quit 新语义：**任意时刻主动退出，或断线 30s 内 grace 到期未归**；30s 窗口仅适用断线场景。
4. 写明退出后账号房间占用立即释放（可立即开新局）、`reconnect` 回原房间被拒的口径。
