# 《潮汐商会》M2 固定任务式基础教程策划方案 v1.0

状态：冻结规则执行稿

依据：`docs/01_rulebook_v1.0.md`、`docs/03_balance.md`、`shared/protocol.md`、`shared/data/cards.json`、`shared/data/contracts.json`、`shared/data/ports.json`、`shared/data/config.json`、`shared/data/events.json`、`tests/new_player_test_plan.md`。

本方案只定义产品行为和验收口径，不修改 `shared/`，不包含代码。

## 1. 产品目标

### 1.1 身份与生命周期（冻结）

- 注册账号的 `#role` 只承载账号长期数据，正式统计使用 `role_id`；账号登录时创建 `PlayerProcess`。
- 游客没有 `#role`、`role_id`、服务端会话或 `PlayerProcess`，只能运行纯客户端教程。刷新或断线后必须重新开始教程，不恢复阶段。
- 游客完成教程后必须注册账号继续，或退出；游客不能进入大厅、创建/加入房间或参加正式对局。
- 教程不产正式统计；Bot 仅为房间临时数据，房间关闭即消失。

1. 让没有桌游经验的玩家在一次可控、可重玩的流程中理解“选一张双用卡，转化资源，再交付订单或争夺港口”的核心循环。
2. 玩家在 10 分钟内完成第一次合法行动，并在 15 分钟内完成固定教程的主要任务，不需要测试人员口头补充规则。
3. 通过固定资源降低随机性，让每个错误都能对应到一个可解释的规则；通过服务端真实结算，避免教程学到与正式局不同的规则。
4. 教程完成后，注册账号可进入 `1 名真人 + 1 名 easy bot` 的正式规则房间；游客必须注册或退出，不能直接进入陪练。
5. 教学过程不制造奖励、正式战绩、胜场、天梯、排行榜或正式局记录。

## 2. 教学与正式局边界

### 2.1 静态说明

静态说明是只读导航内容，按“目标与胜利、选牌与三种用途、资源与货物、六种行动、潮汐与市场、订单与终局”顺序展示。完成说明只代表看完或主动跳过说明，不代表完成教程。

### 2.2 固定任务教程

- 教程是专用 `tutorial` 会话，不是普通房间，不进入 `list_rooms`，不允许普通玩家加入、观战、操作或接收内部状态。
- 教程只有一名真人，不创建 bot，不等待其他玩家；服务端按固定阶段快照提供资源。
- 行动仍使用 `submit_card` 的语义：服务端检查阶段、卡牌归属、卡牌用途、目标、费用、位置、订单条件和潮汐效果。
- 任务切换时由服务端装载下一阶段固定快照。该重置是教学编排，不是金币、VP 或道具奖励；教学快照永不进入正式牌局牌库或统计。
- 教程的阶段快照使用现有数据中的卡牌 UID、订单 ID、港口 ID、货物枚举和潮位枚举，不新增卡牌、订单、港口、货物或数值。
- 教学局可展示局部的即时 VP、金币、市场和潮位变化，但结算结果仅用于本教程任务判定。

### 2.3 Easy bot 陪练

固定教程完成后，默认按钮为“开始 easy bot 陪练”。陪练创建正式规则会话，配置为 `1 名真人 + 1 名 easy bot`，执行 4 轮 × 3 回合、45 秒选牌、正式市场/潮汐/订单/终局规则。陪练不是教程任务的延长，也不能通过固定任务完成接口推进。

注册账号的正式规则 Bot 陪练按既定规则统计并归属 `role_id`；若房间模式为 `practice` 则不统计。游客不能进入陪练。

## 3. 固定资源基线

### 3.1 全局基线

除阶段表另有说明外，每个阶段载入以下固定公共状态：

| 项目 | 固定值 |
|---|---|
| 玩家 | 1 名真人；不显示其他玩家 |
| 手牌 | 表中指定的 5 张既有卡牌；UID 和卡牌面与 `cards.json` 一致 |
| 起始港口 | `east` 东鳞港 |
| 金币 | 3 |
| 潮位 | `rising` 涨潮 |
| 市场 | `salt=3`、`lamp=3`、`silk=4` |
| 公开订单 | `CT01` 盐鳞小单、`CT02` 灯油小单、`CT07` 双货中单 |
| 隐藏订单 | `CT08` 灯丝中单，仅当前玩家私有可见 |
| 牌库/事件 | 不向玩家展示随机顺序；教程不依赖随机抽牌和随机事件 |

`CT01`、`CT02`、`CT07` 均为现有公开订单，`CT08` 为现有隐藏订单。所有订单均为 `port=any`，不会把玩家卡在某个未教学港口。

## 4. 教学状态与入口

业务状态采用基线中的 `not_started`、`in_progress`、`completed`、`skipped`、`exited`。`completed` 仅在 T9 及其完成条件通过后写入；静态说明跳过、教程退出和浏览页面均不能写成完成。

建议的教学内部状态为 `tutorial_stage=T1..T9` 和 `stage_status=active|passed`，但字段名不是本方案对协议的强制规定。登录账号由其 `PlayerProcess` 保存当前阶段；游客不保存服务端阶段，刷新或断线从头开始。

入口规则：

- `not_started`：显示静态说明、开始教程、跳过当前段和退出入口。
- `in_progress`：显示继续当前阶段和重新开始；不得默默创建第二个会话。
- `completed`：显示已完成、查看摘要、重玩教程和开始陪练；重玩不清除完成标记。
- `skipped`/`exited`：显示继续或重新开始；不视为完成。
- 登录账号的完成状态由账号 `role_id` 对应的服务端长期数据保存；游客状态只存在客户端本次教程流程，完成后不得自动迁移到随后注册的账号。

## 5. 任务步骤

### T1：把卡牌留作货物

- 提示：一张卡有行动面、货物面和潮汐面。先把 `C014` 以 `cargo` 打出，并声明 `good=salt`。
- 玩家操作：选择 C014，模式 `cargo`，目标货物为 `salt`。
- 完成条件：服务端确认 C014 属于当前手牌，C014 的货物面为 `wild`，声明合法；货物仓出现 1 个 salt，手牌移除 C014，金币、市场和潮位不变。
- 关键提示：货物仓不是手牌；wild 必须声明货物种类。wild 的潮纹值为 0，不能用来推进潮汐。

### T2：买入货物并观察价格

- 提示：在当前港口用 C013 执行买货，购买 1 个 lamp。购买前 lamp 为 3，付款后市场价格上升。
- 玩家操作：C013，模式 `action`，目标 `{kind:"buy",good:"lamp",count:1}`。
- 完成条件：金币从 3 变为 0，货物仓增加 lamp 1，lamp 价格从 3 变为 4，C013 进入弃牌；salt 仍在货物仓。
- 关键提示：买货最多 2 件且同一种；本次金币不足时不能购买。低潮价格修正只在低潮适用，本阶段为涨潮。

### T3：交付并获得 VP/金币

- 提示：用 C027 交付公开的 `CT01 盐鳞小单`。订单要求 1 个 salt，当前为涨潮，交付还有涨潮 VP 加成。
- 玩家操作：C027，模式 `action`，目标 `{contract_id:"CT01"}`。
- 完成条件：CT01 从公开订单移除，salt 从货物仓扣除，获得 CT01 的 3 VP、1 金币及涨潮额外 1 VP；因此本阶段 VP 变为 4、金币变为 1；salt 市价从 3 降为 2。
- 关键提示：交付必须拥有订单要求的全部货物；交付后订单涉及的每种货物各压价 1 次，不按需求数量重复压价。

### T4：卖货并观察压价

- 提示：用 C018 卖出货物仓中的 lamp。成交按当前价格收金币，成交后 lamp 价格下降。
- 玩家操作：C018，模式 `action`，目标 `{kind:"sell",good:"lamp",count:1}`。
- 完成条件：获得 4 金币，金币从 1 变为 5；lamp 从货物仓移除，lamp 市价从 4 变为 3；C018 进入弃牌。
- 关键提示：卖货固定 1 件；没有对应货物不能卖。满潮时卖货会有临时 +1 收价，本阶段不是满潮。

### T5：扬帆到相邻港口

- 提示：港口是环形相邻的。用 C001 从东鳞港驶往碎星礁，涨潮时基础航行费为 1 金币。
- 玩家操作：C001，模式 `action`，目标 `{to_port:"reef"}`。
- 完成条件：船位从 east 变为 reef，金币从 3 变为 2；C001 进入弃牌。
- 关键提示：只能驶向当前港口的相邻港口；金币不足或目标不是相邻港口时行动被拒绝。

### T6：在当前港口设站

- 提示：用 C034 在所在港口设立商站。商站一旦放置不可移动，终局按港口多数计分。
- 玩家操作：C034，模式 `action`，目标 `{port:"reef"}`。
- 完成条件：金币从 2 变为 0，reef 出现 1 枚本人的商站，C034 进入弃牌。
- 关键提示：设站费用为 2 金币；目标港口必须等于船位；同一港口不能重复放置自己的商站。

### T7：用潮汐秘术改变潮位

- 提示：用 C039 的 `shift` 让潮位前进一格，观察涨潮到满潮的变化。潮位会改变航行、交易或交付的收益。
- 玩家操作：C039，模式 `action`，目标 `{op:"shift",delta:1}`。
- 完成条件：服务端确认潮位由 rising 变为 full，C039 进入弃牌；任务面板显示满潮时航行费降低、卖货有临时加成。
- 关键提示：`delta` 只能为 1 或 -1；潮位是全局公共状态，不能客户端自行改写。事件若按正式时机触发，必须由服务端结算并展示。

### T8：用潮汐用途推进潮汐

- 提示：同一张卡也可以弃置为 `tide`。用 C002 以 tide 打出，潮纹值 1，回合结算后潮位前进一格。
- 玩家操作：C002，模式 `tide`，不带行动目标。
- 完成条件：服务端确认 C002 的潮纹值为 1；结算后潮位由 rising 变为 full，C002 进入弃牌；不增加货物、不执行扬帆。
- 关键提示：tide 不是行动面，不能同时买货、移动或保留货物；潮纹 0 的 wild 不会推进潮位。任务完成以服务端结算后的状态为准。

### T9：顺风的移动加交易

- 提示：顺风先移动，再在新港口完成一次交易。满潮时航行费为 0，卖货临时加 1 金币。
- 玩家操作：C045，模式 `action`，目标 `{to_port:"reef",kind:"sell",good:"salt",count:1}`。
- 完成条件：船位 east→reef，salt 从货物仓移除，金币从 3 变为 7（卖货成交价 3+满潮临时加成 1，同时航行免费）；salt 市价由 3 变为 2；C045 进入弃牌；服务端发送 `tutorial_completed` 等价的明确完成结果。
- 关键提示：顺风的两个部分必须都合法；不能驶向非相邻港口，不能卖不存在的货物，也不能把顺风当作两张卡提交。

## 6. 错误操作与反馈

错误提示分两层：页面在提交前做可用性提示，服务端拒绝后以 `action_rejected` 的 `reason` 为准。客户端不得只显示“操作失败”，也不得根据本地修改绕过服务端。

| 错误 | 玩家可见提示 |
|---|---|
| 不是当前阶段或重复提交 | “这一步已经结算，请等待下一步。” |
| 卡牌不在本人手牌 | “这张卡不属于你的当前手牌，请重新选择。” |
| 模式与任务不符 | “本步骤需要把卡牌留作货物/执行行动/弃置推进潮汐。” |
| 目标港口不相邻 | “只能驶向当前港口相邻的港口。” |
| 金币不足 | “金币不足，无法支付这次行动的费用。” |
| 货物不足或数量非法 | “货物数量不满足这次交易/订单要求。” |
| 订单不可见或不存在 | “这不是你当前可交付的订单。” |
| 重复设站或目标港口不在船位 | “只能在当前港口设站，且同一港口不能重复设站。” |
| tidecraft 参数非法 | “潮汐秘术只能选择查看，或前进/后退一格。” |
| wild 未声明货物 | “万用货物必须先声明要充当的货物。” |
| 教程会话失效 | “教程已结束，请重新开始；不会扣除正式资源。” |
| 状态/账号请求超时 | “暂时无法确认教程状态，请重试；未确认前不会显示完成。” |

错误请求不得改变手牌、货物、金币、VP、订单、港口、潮位、市场、任务进度或完成状态。重复的 `action_id` 必须幂等，不能重复结算。

## 7. 服务端权威要求

1. 登录账号的 `PlayerProcess` 可保存教程阶段；游客教程完全由客户端运行，不创建服务端会话；客户端只渲染固定规则。
2. 服务端从共享数据按 UID/ID读取卡牌和订单定义，拒绝客户端伪造卡牌属性、潮纹、奖励、价格、费用或完成条件。
3. 服务端校验玩家身份、会话归属、当前阶段、当前手牌、模式、目标、资源、港口位置、订单可见性和幂等 `action_id`。
4. 每次成功行动先由服务端结算，再更新任务进度并发送权威快照；客户端不能通过“完成任务”按钮直接完成。
5. 登录账号的教程状态必须有明确的 `tutorial` 类型/标识，并在房间列表、普通房成员、正式 `action_log`、正式 `game_over` 和统计查询中排除；游客教程为纯客户端状态。
6. 同一身份并发开启教程时，服务端只能复用一个会话、拒绝新会话或原子关闭旧会话，不能双重推进、回退阶段或留下孤儿进程。
7. 登录账号刷新/重连恢复最近确认阶段；游客刷新/断线从头开始；退出后不留下服务端会话、玩家占位或可见房间。
8. 教程完成写入必须幂等。登录账号写入其 `role_id` 的教程状态；游客仅完成当前客户端流程，不能把游客状态写入随后注册的账号。

## 8. 隐私边界

- 本人可见：本人完整手牌 UID、货物明细、CT08 隐藏订单、当前教学进度和错误详情。
- 公共可见：教学说明、公共订单、港口、潮位、市场以及本教程为教学所需的本人金币/VP展示。
- 不应存在的其他信息：其他玩家手牌、其他玩家隐藏订单、普通房牌库顺序、服务器内部固定脚本剩余步骤、未触发事件堆顺序。
- 管理端日志只记录会话 ID、阶段、行动结果和错误类别等必要诊断信息，不记录完整手牌或隐藏订单内容；若必须记录用于安全审计，应脱敏并限制管理员访问。
- 教程快照不得通过普通房间广播、`list_rooms`、排行榜、战绩、正式行动日志或浏览器可读的他人字段泄漏。

## 9. 完成、退出与重玩

- 完成：T1-T9 全部通过后，登录账号显示教程摘要和“开始 easy bot 陪练”；游客显示“注册账号继续”或“退出”。不发奖励，不写正式战绩。
- 开始前退出：不创建教学会话或立即释放，不写完成。
- 进行中退出：二次确认后结束当前会话，状态为 `exited` 或等价未完成状态；重新开始从 T1 固定快照开始，不恢复半步资源。
- 取消退出：维持当前阶段和快照，不重复提交行动。
- 跳过静态说明：进入教程入口或后续引导，但不写教程完成；游客仍只能完成纯客户端教程后注册或退出。
- 完成后重玩：重新创建 T1-T9 的固定流程；原完成标记继续为 completed，重玩不覆盖完成时间/版本，不生成正式数据。
- 登录账号断线/刷新：恢复最近确认阶段；游客断线/刷新：从头开始，不显示虚假的完成。
- 版本变化：旧快照版本不可继续时，提示“教程版本已更新”，由服务端安全地重新开始；不得用未知字段误标完成。

## 10. 未覆盖机制

本版教程不要求完整演示以下机制，但静态说明须给出最小解释或明确“将在正式局遇到”：

- 45 秒选牌超时、断线 60 秒重连和真人托管。
- 退潮、低潮的航行/买货/隐藏订单修正，以及各潮位事件 EV01-EV06 的完整组合。
- `peek` 查看事件、后退潮位、潮纹多张同时结算和多人同时亮牌/座位顺序。

不应在教程中用脚本模拟这些机制并声称玩家已经掌握；它们由 easy bot 陪练和正式局回归覆盖。

## 11. 与 easy bot 陪练的衔接

完成页用三条复习卡总结：

- “卡牌可以执行行动、留作货物，或弃置推动潮汐。”
- “买货抬价、卖货和交付压价；订单通常比单纯卖货更值得优先考虑。”
- “潮位会改变费用和收益，商站在终局按港口多数计分。”

注册账号后点击陪练，创建 1 名账号真人 + 1 名 easy bot，不要求第二名真人，也不把 T1-T9 的快照、金币、手牌、VP、订单或港口带入。陪练开局按正式设置重新生成：5 张手牌、3 金币、east、rising、正式市场和订单。界面明确标注“正式规则陪练”“人机·简单”。游客不能直接进入陪练。

陪练中的非法行动、断线、重连、Bot 合法行动和终局按既有正式规则处理；普通账号 + Bot 正式规则局按既定规则统计并归属 `role_id`，`practice` 局不统计；陪练退出后账号回大厅。

## 12. 验收标准

### P0 功能与权威

- 注册账号能依次完成静态说明、T1-T9 固定教程和默认 1+1 easy bot 正式规则房间；游客只能完成纯客户端教程后注册或退出。
- 每次新开/重玩教程的 9 个阶段快照与第 3.2 节完全一致，卡牌/订单 ID 均能在 shared 数据中找到。
- T1-T9 的合法行动真实经过服务端校验，状态变化符合规则书；错误请求不改变任何权威状态。
- T9 只能在 salt 存在、reef 相邻、满潮费用规则满足时完成；完成不能由客户端伪造。
- 教学会话不出现在普通房列表或普通房成员中，普通房与教程并行时消息不串线。
- 教程完成、退出、重玩、刷新、重连和重复 `action_id` 均无重复结算、状态回退、卡死或资源泄漏。
- 登录账号完成状态按 `role_id` 跨浏览器/设备保留；游客刷新/断线重开，且游客状态不迁移到登录账号。
- 教程、游客、Bot 和 `practice` 不改变正式统计；普通账号 + Bot 正式规则局按既定规则改变其 `role_id` 统计。

### P1 体验与安全

- 桌面和窄屏移动端的提示、手牌、货物、订单、潮位、市场和退出确认均可操作且不遮挡。
- 两名无桌游经验受试者均在 10 分钟内完成首次合法行动。
- 客户端篡改展示资源、卡牌属性、任务进度、完成请求、目标港口或他人会话 ID 时，服务端拒绝且无状态污染。
- 并发打开两个教程时按既定策略安全处理；账号服务失败、本地存储不可写或数据损坏时不误判完成。
- easy bot 陪练不等待第二名真人，能按正式规则推进至终局；具体回归沿用基线 NP-G 用例。

## 13. 已废止旧规则与非阻塞说明

以下旧口径废止，不得继续实现：

1. **协议缺少教程会话协议。** 当前 `shared/protocol.md` 只有普通房间的 `create_room`/`game_started`/`state_sync`/`game_over`，没有开始教程、阶段快照、教程完成、教程退出、教程状态查询或 `tutorial` 会话标识。需由主协调决定复用现有消息还是提出协议扩展，并同步 shared。
2. **固定资源没有配置入口。** `config.json` 未定义教程快照、阶段任务或固定订单。方案假定服务端内置一份由 shared ID 组成的策划配置；若要求配置化，需主协调在 shared 增加协议/数据定义，不能由本文件直接修改。
3. `player_token` 统计身份、含 Bot 局减半、教程/陪练统计待裁决的旧规则废止；正式统计统一使用 `role_id`，普通账号 + Bot 正式规则局正常统计，`practice` 不统计。
4. **事件触发在教程阶段的处理未完全落在协议。** 规则书/协议定义了事件效果，但消息列表没有独立事件消息。T7/T8 若触发事件，需确认通过 `state_sync`/`action_log` 展示；固定教程不应依赖随机事件，否则快照验收不稳定。
5. **教学阶段重置语义未被现有正式规则定义。** 本方案需要服务端在每个任务通过后装载下一固定快照。需主协调确认这是专用教学状态机行为，而非普通局 `state_sync` 可推导行为。

本稿已按冻结规则统一产品口径；协议字段和实现细节仍由主协调在 `shared/`、前后端落实，本文件不修改其他目录。
